# 简洁 TS/JS 代码风格

写出短而直接、与周围代码一致的实现。目标是减少阅读负担，不是让变量数或行数最少。

默认像手写代码一样按业务顺序展开：短包装直接返回，多步骤保留清楚的局部变量；需要状态时用闭包、原生集合或简单类，不为了“函数式”“零变量”或统一架构绕一层。

## 工作流程

1. 读取目标文件和直接相关的调用方、工具模块；有明确目标时不必扫描整个仓库。
2. 查看目标项目的开发说明、格式及类型配置。明确的用户要求和项目约束优先于本 Skill 的默认风格。
3. 确认需要保留的行为：返回值、失败分支、外部副作用、执行顺序和资源释放。
4. 在请求范围内直接修改，优先复用现有能力；不顺带全仓格式化、升级依赖或改造架构。
5. 运行适用的格式检查、类型检查、lint 和相关测试。只报告实际执行的结果，简短说明改动与未验证的部分。

常规小改动直接完成，不默认启动多代理审查或模型对比测试。

## 格式与命名

目标项目没有不同约定时，采用以下默认格式：

| 项目 | 默认值 |
| --- | --- |
| 行宽 | 150，由格式器决定换行，不刻意塞满 |
| 缩进 | 两空格，不用 Tab |
| 分号 | 不写；必要时保留防止自动分号插入歧义的分隔 |
| 字符串 | 单引号；插值用模板字符串 |
| 对象属性引号 | 仅必要时保留 |
| 尾逗号 | 不加 |
| 对象花括号 | 内侧保留空格 |
| 换行符 | LF |
| 箭头函数参数 | 保留括号，沿用项目的 `arrowParens` 配置时除外 |
| JSX / 模板属性引号 | 双引号；表达式内的 JS 字符串仍用单引号 |

- 函数、变量和普通对象使用 `camelCase`；类型、接口和类使用 `PascalCase`。
- 两空格是没有配置时的回退，不把 Tab 缩进的项目改成空格，也不逐字模仿博客代码块中不统一的排版。
- 文件名沿用同目录习惯，避免为统一命名改动无关文件。
- `ctx`、`res`、`db`、`req`、`dir`、`uri` 等上下文明确的短名可以保留；循环、索引和算法中的 `i`、`j`、`l`、`r` 也很自然，不强行扩成长名称。领域状态用 `loading`、`timer`、`visibleMap` 这类直接名称。
- 常量按现有约定命名，不是所有 `const` 都写成大写。
- 保持现有导入顺序和模块形式。新模块在环境支持时优先 ESM，不为了风格迁移已有 CommonJS 模块。
- 注释保持周围代码的语言；没有约定时使用简短中文。函数前的“防抖”“获取文章”、步骤前的“初始化”“清空缓存”等短功能注释可以保留；关键状态旁解释用途或原因，不给每次普通赋值都写注释。
- 对外接口文档、生成的类型说明和使用示例有实际用途，不因追求简洁而删除。

## 表达式、变量与控制流

### 减少无职责的中间变量

- 仅使用一次、表达式短且只是转交的值，直接用于调用或返回；“只用一次”不等于“多余”。
- 只需要对象的一个或少数字段时，可以直接解构，避免保留整个对象并重复属性访问。
- 无额外职责的包装函数优先直接返回原调用，避免 `const result = ...; return result`；保留既有同步抛错与 Promise 拒绝的边界。
- 布尔结果直接表达，不写冗长的 `if/else` 返回。
- 默认值根据语义选择 `??` 或 `||`，不机械互换：空字符串、零和 `false` 是否触发回退是行为的一部分。

### 保留真正有职责的变量

保留用于复用、命名业务步骤、解释条件、保存状态、类型收窄或保证执行时序的变量，例如响应 `res`、数据库句柄 `db`、格式化的年月日、列表索引 `itemIndex`、配置快照、取消控制器和提前注册的事件监听 Promise。即使只用一次，也可以让“读取 → 处理 → 更新”更容易顺着看。

不要为了少一个变量而重复读取配置、执行 I/O、解析数据或计算复杂表达式。不要把多步骤流程塞进多层嵌套 `await`、连续赋值或难读的副作用表达式。简单的二选一用三元表达式即可，复杂分支用 `if/else`，不刻意消灭所有 `else`。

### 直接表达正常路径

- 工具函数、接口包装和局部回调优先 `const fn = (...) => ...`，按需使用具名导出；简单包装适合表达式体，多步骤逻辑用块体。不为了省一对花括号改写周围一致的块体。
- 箭头函数不是机械替换规则：依赖动态 `this`、构造行为或声明提升的函数保留合适的形式。
- 前置条件用早返回或直接抛错，减少层层 `else`。
- 简单的 `if (...) return ...`、`if (...) throw ...` 可以不加花括号；多语句分支保留花括号。
- 纯转换适合 `map`、`filter`、`some`、`every`；遍历调用可用 `forEach`；累积状态、提前退出或有异步顺序时用 `for` / `for...of`。不为了“函数式”把清楚的循环改成复杂 `reduce`。

### 只封装真实的能力

- 参数少且含义清楚时直接传参；多个可选行为适合一个小 `options` 对象并就地解构默认值，不统一改成参数对象或配置构建器。
- 优先复用现有工具和原生 `Map`、`Set`、`WeakMap`、数组。确有复用或独立职责时抽小函数；只用一次但表达清楚的 `resetCache`、`stop` 也可以保留。
- 定时器、缓存句柄等局部状态适合闭包；按需返回 `{ start, stop }` 或给函数附加 `cancel`，不再包一层工厂或管理器。
- EventBus、LRU、撤销重做等围绕状态和多种操作的能力适合简单类。直接写字段和方法，不强行改成纯函数，也不叠加接口层、策略类、基类或依赖注入。保留方法的链式返回值和回调身份。
- 普通接口调用或一次性操作不额外引入类、通用执行器或框架。相似的几行代码不自动意味着需要通用封装。

## 类型与异步边界

- 使用 `const`；只有需要重新赋值时使用 `let`。
- 默认利用类型推断，不为显而易见的局部变量和返回值重复标注类型；项目要求显式公共签名时保留。
- 为参数、外部数据和不能可靠推断的边界提供有意义的类型。对象参数、组件 Props 和复用的数据结构优先简单 `interface`；联合类型、函数类型和类型运算用 `type`，已有约定优先；小的局部选项可内联。
- 能从已有定义推导时使用 `typeof`、`ReturnType` 或索引访问类型，不重复手写一份结构。泛型服务于实际参数与结果的关联，不为普通业务代码堆条件类型和多层工具类型。
- 对不可信字段优先使用 `unknown` 并做运行时校验，不用类型断言代替校验。沿用已有校验边界，不借风格调整给已验证的内部数据再加层层防御或回退。
- 不机械禁止已有的 `any`，也不为了省代码而给新逻辑随意加 `any`。外部兼容类型和生成声明沿用其必要约束。
- JavaScript 文件保持原语言形式，不为了应用类型规则擅自迁移成 TypeScript；必要时沿用 JSDoc。
- 多步骤异步代码优先 `async/await`，让请求、解析和状态更新顺着写；短 `.catch()` / `.then()` 用于局部回退、单步回调或直接转换，不为了消掉 `res` 把整段代码串成链。
- 合并 Promise 链时保持错误边界：等待响应的失败和解析 JSON 的失败不一定应该由同一个 `.catch()` 处理。
- `try/finally` 用于释放已经取得的资源。不要内联掉会改变异常传播或清理顺序的 `await`，包括某些 `return await`。
- 并行执行只用于没有顺序依赖的操作；风格简化不自动改成 `Promise.all`。
- 不删除用于控制后续动作的状态结果，例如 `false` 表示无需更新、`null` 表示失败；先确认调用方如何使用它们。

## 组件与局部组织

仅处理组件或 Hook 时应用这些偏好，不向普通工具模块引入框架：

- React 页面和组件优先沿用具名 `function` / `export default function Page()`，内部处理方法用箭头函数；不统一改成 `React.FC`。
- 状态、派生值、事件处理和生命周期按周围代码自然分组。短的取值、跳转和单次调用可以直接写在 JSX / 模板回调里，多步骤再命名为局部方法。
- 表格列、菜单、请求参数等直接用对象或数组描述，不只为组织几项配置引入 builder 或注册中心。
- 使用框架原有的 `useState`、`useRef`、`computed`、`watch` 等。确有跨组件复用或独立生命周期职责才抽 Hook / composable，不给每个事件都创建一个。
- 按实际需要使用 `useMemo` / `useCallback`，不默认给所有函数和计算加缓存；已有实例稳定性、闭包取值或依赖关系有意义时保留。
- 保留初始化锁、加载状态、测量快照、定时器和清理逻辑。阻止默认事件等必要动作放在可能跳过业务的早返回、节流或状态锁之前；异步加载完成前不触发写回。

## 环境与职责

- 先确认运行环境和框架，沿用其文件访问、路径处理、生命周期和状态管理方式，不把某个环境的 API 当成通用依赖。
- 工具函数优先返回结果或抛错，由调用边界决定最终反馈；已有职责明确时不借风格调整搬迁它们。请求层已统一处理错误时，不在每个调用方重复提示或打印；不把空 `catch` 当成默认写法。
- 保持用户可见消息、国际化键和占位符，不在精简时擅自重写提示内容。
- 保留凭据存储和敏感信息处理边界，不为了少几行将秘密放进配置、普通文件或日志。
- 同步 I/O 是否合适取决于脚本、服务和交互场景，不机械统一成同步或异步。
- 修改生成内容时找到真实的数据源或生成器，不直接修改标记为“请勿手改”的产物。

## 检查与交付

先读取实际配置和包管理器信息，再选择已有的检查命令。不要假定所有项目都有 `check-types`、`lint` 或相同的测试环境，也不要为了运行检查安装新的工具。

对修改文件执行适用的格式检查，对类型和行为变化运行相关静态检查及测试。无法运行时说清原因；格式检查不能证明运行行为正确。

完成后简短说明：改了什么、保留了哪些重要边界、哪些检查通过，以及哪些没有运行。不自动提交、推送或修改无关配置。
