# 简洁 TS/JS 代码风格

写出短而直接、与周围代码一致的实现。目标是降低阅读和维护成本，不是让行数或变量最少。

## 规则加载与示例查阅

先以本文作为默认执行规范。[references/examples.md](references/examples.md) 补充具体表达方式、适用条件和反例，不要求每次使用本 Skill 都完整读取。

- 本文对当前场景已有明确要求，且能确定如何应用时，直接按本文执行，不必读取示例。
- 对风格写法、规则取舍或适用边界拿不准，或者本文缺少当前场景的对应要求时，必须先读取 `references/examples.md` 的相关章节，再输出、修改或评审对应的 TS/JS 代码。
- 不等待用户要求查阅；上述任一条件成立时，任务简单、只改一行或已使用其他 Skill 都不是跳过理由。
- 查阅时同时阅读相关代码、解释、适用条件和反例，不能只模仿改后代码；涉及多个章节时补读所需部分，不要求无关章节一起通读。
- 当前上下文已完整读取所需章节且文件未变化时无需重复读取；只有摘要或在其他会话读过，不算已查阅相关示例。
- 若无法读取，先检查 Skill 目录和相对路径；仍无法读取时说明缺失，不宣称已根据示例确认。
- 示例中的关键约束仍需遵守，但不能机械套用；用户要求、项目规范和真实行为始终优先。

## 触发与适用范围

- 只要接下来要写、输出、修改或评审 TS/JS 代码，就必须先加载本 Skill，不等待用户点名，也不要求用户提到“简洁”“风格”或“重构”。
- 根据目标文件、项目技术栈和将要输出的代码判断；用户没有说 TS/JS、只改一行或任务很简单，都不能作为跳过理由。
- 覆盖前后端、Node.js、React、Vue、Svelte、工具函数、配置文件、脚本、测试，以及回答或文档中的 TS/JS 示例代码。
- 与其他 Skill 配合使用：其他 Skill 负责各自的流程，本 Skill 负责 TS/JS 代码风格，不能以已加载其他 Skill 为由省略。
- 任务后续继续适用，不反复询问或宣告。
- 只处理授权范围；用户要求、仓库规范和真实行为优先。
- 不编写、修改、评审或输出 TS/JS 代码的纯解释、纯文档及其他语言任务不触发。

## 默认能力优先

先看现有组件、工具、框架和平台是否已经提供所需行为。默认能力能满足需求时，直接配置或调用，不自行重做。

- 不为已有默认值再写生成函数、列表、状态或适配层。
- 不用自定义实现替换可用的原生控件、项目组件或成熟 API。
- 例如日期控件已有默认可选范围时，直接使用，不手动生成年份数组；原生选择器能满足需求时，不改成自由文本输入。
- 只有默认行为无法满足明确需求时才扩展，并只补缺失部分。
- 简单校验优先清楚的条件、集合或已有校验工具，不堆难读的正则和重复规则。

## 直接表达业务流程

- 短包装直接返回调用结果；多步骤流程按“读取 → 判断 → 执行 → 更新”自然展开。
- 前置条件早返回，减少嵌套；简单二选一可用三元，复杂分支使用清楚的 `if/else`。
- 不创建只转交参数或结果的函数、变量、类、Hook、工厂和配置层。
- 只有存在复用、独立职责或生命周期边界时才抽取。
- 相似几行代码不自动意味着需要通用抽象。

## 变量与控制流

- 默认 `const`，需要重新赋值时才用 `let`。
- 仅使用一次、表达式短且没有命名价值的中间值直接内联。
- 保留用于复用、解释业务步骤、类型收窄、保存状态或保证时序的变量。
- 不重复执行 I/O、解析、配置读取或复杂计算来减少变量。
- 纯转换使用 `map` / `filter` / `some`；需要累积状态、提前退出或异步顺序时使用循环。

## 状态与抽象

- 局部状态优先闭包、原生集合和框架自带状态能力。
- 少量进程内共享状态使用普通模块对象，不为“单例”形式增加 `getInstance()`。
- 状态与多种操作确实构成一个能力时可使用简单类，不叠加接口、基类、策略或依赖注入。
- 优先 `Map` / `Set`；对象生命周期绑定且无需遍历时可用 `WeakMap` / `WeakSet`。

## 类型与异步

- 利用类型推断；为参数、外部数据、组件 Props 和公共边界提供必要类型。
- 对象结构优先简单 `interface`，联合和函数类型使用 `type`；泛型只表达真实关联。
- 不用 `any`、断言或非空断言绕过可正常收窄的问题；不可信数据使用 `unknown` 并校验。
- 多步骤异步逻辑优先 `async/await`；短局部转换或回退可使用 Promise 链。
- 保持原有异常传播、重试、清理和执行顺序；资源释放使用 `try/finally`。
- 只并行执行没有顺序依赖的操作。

## 组件代码

- React 页面和组件沿用项目的具名函数习惯，内部事件处理使用局部箭头函数。
- 状态、派生值、事件和生命周期按阅读顺序组织。
- 短操作可直接写在 JSX 回调中；多步骤再命名。
- 不默认添加 `useMemo` / `useCallback`，仅在计算成本、引用稳定性或依赖关系确有意义时使用。
- 表格列、菜单和表单配置直接使用对象或数组描述，不引入 builder。
- 保留定时器、取消控制器、初始化锁和清理逻辑。

## 格式与命名

项目没有约定时使用：两空格、单引号、无分号、LF、约 150 行宽、JSX 双引号。

- 普通标识符使用 `camelCase`，类型和类使用 `PascalCase`。
- 沿用目录中的文件名、导入顺序、模块形式和缩写；注释按下节规范执行。
- 短名在上下文清楚时可以保留，不机械扩写；同一领域概念保持一致。
- 不为应用风格而全仓格式化、迁移模块、升级依赖或修改公开契约。

## 注释规范

普通 TS/JS 逻辑严格使用短中文 `//` 注释，不只笼统要求“保留注释”。

- `//` 后留一个空格。独立注释与对应代码缩进一致，紧贴被解释的代码之前；行尾注释与代码之间留一个空格。
- 业务阶段、Effect 的职责，以及需要解释原因、条件或时序的逻辑，使用上方独立注释。直接说清这一段做什么或为什么这样做，不写函数说明模板。
- 状态含义、容量处理或单行副作用使用简短行尾注释；说明较长时移到上方，不硬塞成长行。
- 使用自然、直接的中文，允许混写代码中的标识符；必要的补充说明使用半角括号。规范规定、状态锁和特殊返回规则可以写完整的一句话，不为追求短而省略关键条件。
- 注释重点解释业务目的、非直观约束和执行顺序，不逐行翻译代码。不要求每个变量、函数、分支都有注释，不添加“定义变量”“调用函数”等无信息说明。
- 保留有价值的短中文功能注释和行尾说明，只在行为变化时同步修正；不得为了“简洁”删除必要的初始化、提前返回、容量淘汰或副作用说明。
- 不默认生成英文注释、`/** ... */`、`/* ... */` 或 `@param` / `@returns` 模板，不把短说明扩成文档段落。只有明确的用户要求、项目规范或工具链需要时才使用文档注释；JSX 标记内部必须注释时使用其语法要求的 `{/* 简短中文 */}`，不将此例外扩展到普通逻辑。

## 实施与交付

1. 读取目标文件、直接调用方和项目配置。
2. 明确保留的返回值、失败分支、副作用、时序与资源释放。
3. 先复用现有能力，再做最小充分修改。
4. 只运行项目真实存在且适合本次改动的格式、类型、lint 或测试命令。
5. 简短报告改动、实际验证和未验证部分，不自动提交或推送。

只有用户要求验证 Skill 效果时才使用 [evals/evals.json](evals/evals.json)。它是验证材料，不替代上述规则加载和示例查阅流程。
