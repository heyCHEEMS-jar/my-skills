# 传播与体验参考

只在用户优化已有产品、核心玩法、获客传播或跨日留存时读取。它补充 `micro-product-operator`，不取代机会筛选、商业判断和运营闭环。

## 一、先找一个招牌体验

不要先增加模式数量。选出最值得录屏和分享的一种体验，检查：

- 静音播放 3～10 秒，陌生人是否看懂；
- 用户是否亲手参与，而不是被动看普通动画；
- 每次操作是否推进状态，而不是反复回到原样；
- 是否有清晰的蓄力、爆发和结束；
- 是否让用户主动重玩、保存、录屏或询问分享。

体验型产品可使用以下节奏：

```text
预期 → 蓄力 → 接触 → 短暂停顿 → 爆发 → 余震 → 结果
```

按材质和场景选择反馈：永久形变、镜头反应、粒子残留、分档声音、轻中重震动、物理惯性和环境反应。不同强度不能只改数字；声音、震动、画面或结果至少有两层变化。

极简界面与强体验不冲突。首屏只保留当前任务和必要动作，把视觉复杂度集中在招牌瞬间。

## 二、十秒传播模板

没有现成流量时，让产品本身持续产生素材：

```text
0～2 秒：具体触发场景
2～7 秒：招牌过程
7～9 秒：结果或反差
9～10 秒：低干扰入口
```

触发场景必须具体，例如“下班前收到一句方便开个会吗”，而不是“年轻人的解压神器”。同一过程可批量替换触发句、输入、皮肤、声音、结果和累计阶段。

短视频第一帧直接展示问题或动作，不先放 Logo 和说明。

## 三、分享闭环

完整闭环是：

```text
完成值得展示的行为
→ 生成过程或结果
→ 接收者无需说明就能理解
→ 点击后直接体验同款
→ 生成自己的版本并再次传播
```

遮住产品名、二维码和邀请话术后，用户仍愿意发，才说明分享物本身有价值。动态过程是核心爽点时，不默认用固定结果卡代替。

避免分享后才能继续、拉固定人数解锁核心能力、虚构参与人数，以及默认带出用户原文或敏感信息。

## 四、跨日回访

首轮体验成立后再设计留存。轻量娱乐和情绪产品优先使用累计有效天数：

- 每天可多次使用；
- 每个自然日最多推进一次长期进度；
- 中断不清零；
- 首次完成后预告最近一个真实解锁；
- 解锁应加强核心体验，而不是普通换色。

先实现最近一个解锁并验证回访，再制作完整 7 天内容。广告只在完成和回访信号成立后测试，适合临时皮肤、额外结果或提前体验，不用来跳过全部回访理由。

## 五、验证顺序

### 10 人无讲解体验

记录原始人数：

- 3 秒内开始；
- 自己完成；
- 主动再玩；
- 明确提到招牌反馈；
- 保存、录屏或询问分享；
- 卡住位置是否集中。

不要只问“好玩吗”。

### 100 人增长验证

提前定义：

- 首次完成；
- 保存/发起分享；
- 邀请打开与邀请完成；
- 七天内跨自然日再次完成；
- 付费咨询或广告行为；
- 继续、转向和停止条件。

“七天内回来”和“第七日当天回来”不是同一个指标。小样本先报人数，再附百分比。

## 六、按漏斗决定下一步

```text
没人停留 → 修触发场景和前两秒
打开但不开始 → 修首屏和理解成本
开始但不完成 → 修核心流程和反馈
完成但不展示 → 修过程/结果的表达价值
有人分享但接收者不完成 → 修接收路径
没有跨日回来 → 修下一次期待
有人回来但不付费 → 修付费主体和权益
```

每轮只选择一个主要问题。不要同时重做首页、增加多种模式、换分享结果和接广告。
