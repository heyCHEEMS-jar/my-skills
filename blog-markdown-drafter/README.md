# blog-markdown-drafter

## 简介

一个面向个人技术博客的写作 Skill，帮助 AI 编程助手把开发记录、代码、报错和零散笔记整理成中文 Markdown 初稿。

**先问清事情怎么发生，再写成像本人记录的文章。**

- 默认分轮协作：还原真实事件链 → 确认链路、重点与范围 → 结构与小段试写 → 完成全文；关键细节不清楚时继续询问。
- 只有主题或一份长稿，都不表示事实已经齐全。先问清实际动作、发现、依据和结果，不凭草稿的篇幅猜作者经历。
- 区分作者亲自尝试、工具或他人协助、资料说明和未验证判断；确认作者了解和验证到哪一层，不把一次排查写成深入原理研究。
- 提供博客、样文或作者终稿时，先看实际用词与删改，不只模仿排版。
- 从具体事情切入，按真正影响理解的转折往下写；访谈问得细，不意味着正文要保留所有细节。
- 默认直接、自然地叙述技术事实；短段、问句和口语转折按作者样文使用，不把它们当作个人博客的固定标记。
- 支持踩坑记录、选型经历、快速上手、手写实现、速查合集和概念解释，不统一套模板，也不为纯概念强造个人经历。
- 代码、表格和资料按作用使用；作者查资料或工具协助若是事件转折，就保留，助手自己的核实不冒充作者经历。
- 保持技术事实和证据边界，不编造测试、性能数字、心理活动或引用，讲到实际结果和取舍就停。
- 明确要求“不用问”“直接出稿”时才跳过相应协作；“只给正文”“结构你定”不代表允许猜事实。
- 只输出初稿或保存到授权位置，不擅自修改业务项目、构建或发布博客。

技术事实与证据是底线；写作偏好按用户本次要求、目标博客已有格式和本 Skill 的默认风格选择。它不替代技术验证，不为了模仿作者而保留错误解释。

逐轮询问示例见 [references/event-chain-interview.md](references/event-chain-interview.md)，写作要点见 [references/style-analysis.md](references/style-analysis.md)，原创正文示例见 [references/writing-examples.md](references/writing-examples.md)。这些示例用于说明可迁移的方法，不要求每篇文章走同一条排查路径。

## 安装

本项目以文档形式提供 Skill，没有可执行源码、依赖清单或构建脚本，不需要运行 `npm install`。

1. 获取本 Skill 的完整目录，保留 `SKILL.md` 及其引用文件。
2. 将目录放入所用 AI 编程助手支持的 Skill 目录。
3. 加载 Skill；具体安装路径与发现机制以宿主工具为准。

## 使用

加载 Skill 后，可以提供主题、开发记录、代码或已有初稿。助手先复述已知事实，围绕事件链中的下一处空白询问；问清关键细节后，再确认要讲什么和写到哪一层，给结构与试写。确认后才完成正文。

```text
把这次日志排查整理成博客，结构不用照原稿。
```

这个请求默认进入事实询问，而不是直接生成文章。概念解释、速查或教学实现没有亲历事件时，确认理解问题、内容范围和示例需要即可。纯文字润色且事实已经确认时，不重新做整套访谈。

## 回归用例

[evals/evals.json](evals/evals.json) 保存手动回归用例。先输入每个用例的 `prompt`，存在 `follow_up_turns` 时再按顺序继续输入，逐轮对照预期行为。用例覆盖事实询问、成稿门槛、直接出稿例外和正文风格。

用例文件不是已通过的评估报告，当前状态仍为 `manual_cases_not_model_evaluated`。
