# markdown-drafter

## 简介

一个面向个人技术博客的写作 Skill，帮助 AI 编程助手把开发记录、代码、报错和零散笔记整理成中文 Markdown 初稿。

**像本人记录事情，而不是只模仿排版。**

- 提供博客或样文时，先看作者实际的用词、衔接、解释方式和收尾，再校准文章语气。
- 从正在做的功能和具体问题切入，跟着事情往下写，不先预告提纲或铺行业背景。
- 使用短段落、自然追问和日常类比解释机制，不靠口头禅、强情绪或网络俚语装随意。
- 支持踩坑记录、选型经历、快速上手、手写实现、速查合集和概念解释，不统一套模板。
- 保留关键代码与因果关系，删掉重复总结、营销金句和未经提供的心理活动，讲完就停。
- 保持技术事实和证据边界，不编造作者经历、测试结果、性能数字或引用，也不堆重复免责声明。
- 只输出初稿或保存到授权位置，不擅自修改业务项目、构建或发布博客。

> [!IMPORTANT]
> 技术事实与证据是底线；写作偏好按用户本次要求、目标博客已有格式和本 Skill 的默认风格选择。它不替代技术验证，不为了模仿作者而保留错误解释。

风格结合 [博客](https://mizuki.heycheems.top/)中的技术文章提炼；只总结稳定的表达习惯，不照搬原文、错误示例或教学简化。写作要点见 [references/style-analysis.md](references/style-analysis.md)，原创示例见 [references/writing-examples.md](references/writing-examples.md)。

## 安装

本项目以文档形式提供 Skill，没有可执行源码、依赖清单或构建脚本，不需要运行 `npm install`。

1. 获取完整的 `markdown-drafter` 目录。
2. 将目录放入所用 AI 编程助手支持的 Skill 目录。
3. 加载 Skill；具体安装路径与发现机制以宿主工具为准。

## 使用

### 用自然语言提出需求

加载 Skill 后，可以结合开发记录、代码或已有初稿提出请求：

```text
把这段编译器选型经历写成博客，按我的博客口吻，别写成标准化复盘。
```

最好提供具体材料和可参考的文章。没有真实经历也能写概念解释或中性示例，但不会替你写“我测试过”。

### 示例：从复盘腔改成事情本身

以下是假设作者已提供开发经历的原创示例，不代表真实项目或测试结果。

改前：

```text
这次选型让我重新理解了功能约束与交付约束。面对性能与可用性的双重挑战，我重新排列了优先级，最终选择了一条更适合用户的交付路径。
```

改后：

```text
最近在给插件写编译推送功能，需要先把组件代码转换后上传。想着转换速度快一点，先试了一个原生编译器。

编译没问题，但要让同一份安装包兼容几个平台，就得把对应的原生依赖一起带上，包一下大了不少。后来换成 WASM，少带了几份平台二进制，代价是接受一点转换速度的损失。
```

示例中的第一人称和性能判断必须有作者材料支持；没有材料时用中性场景，不照抄经历。
