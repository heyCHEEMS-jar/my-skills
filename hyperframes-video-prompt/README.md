# hyperframes-video-prompt

![HyperFrames](https://img.shields.io/badge/HyperFrames-Video-7C3AED)

## 简介

一个为HyperFrames确认整体展现形式与声音方案、构思3D空间分镜、组织时间轴并按需交付旁白稿的Skill。

**只要用户要用 HyperFrames 制作视频就触发；制作前显式确认成片参数，用户没有决定的事项不擅自补默认值。**

先用开放式问题询问整体展现形式与参考，不预设火柴人、角色动画、实拍或固定风格套餐。再分批问清所有适用的内容、比例、背景、空间风格、角色或物品、镜头光影、文字、声音、素材、工具与交付要求；已确认的不重复，不适用的跳过。平台和“横屏/竖屏”不能代替准确比例确认，用户确认或明确授权代选后才采用参数。

重点先构思3D分镜、空间调度和相机叙事，再选择技术实现，而不是把对象排在固定2D平面视图上。用户选择纯2D时仍尊重该选择；3D分镜思维不意味着自动把成片做成全3D。

> [!IMPORTANT]
> 用户本次要求优先。不默认添加人物、火柴人、字幕、配乐、地面或某个库。只有选择火柴人时，才应用线条绘制规则；仍保留行动驱动、非PPT与事实准确原则。

## 安装

安装Skill本身只需文档，不需要运行 `npm install`；实际视频制作可以在授权范围内使用额外依赖或Blender。

1. 获取完整的 `hyperframes-video-prompt` 目录。
2. 放入所用 AI 编程助手支持的 Skill 目录。
3. 按宿主工具的方式加载 Skill。

## 使用

### 示例：知识类视频

```text
用 HyperFrames 做一个XXX的3分钟视频。
```

### 示例：软件 UI 教程

```text
用 HyperFrames 做一个90秒教程，演示XXX。
```

制作前先开放询问，例如：

```text
1. 这条视频给谁看，希望观众看完记住什么？
2. 你希望整体用什么形式展现？有没有参考或明确不想要的形式？
3. 视频要多长、发布到哪里？准确画面比例和输出规格是什么？
4. 背景、空间层次和镜头给人的感觉，你有哪些偏好？
```

随后根据形式询问角色或物品、动作、文字、字幕、素材、分辨率、帧率、格式、保存位置、允许的工具与安装/渲染限制。声音方面单独确认是否需要配音或旁白、背景音乐、环境声、动作/UI/转场音效；需要哪项再追问声音倾向、节奏、音量关系、素材来源与交付方式。“只写旁白稿”和“实际生成配音”也要分开确认，不能因用户选择一种声音就自动加上其他声音。每轮最多四组问题。需要选项时只给单个维度的方向性提示，不把角色、配色、镜头和声音捆绑成套餐。全部确认后复述清单，获得确认再生成；只有明确授权时才代选。

确认后交付；需要旁白时增加独立旁白稿，无旁白或只要提示词时不强制创建第二份文件：

```text
[主题]-HyperFrames提示词.md
[主题]-普通话旁白.md
```

## 分镜与实现原则

- 每段先设计空间起点、对象行动、相机观察、结果与转场出口；近中远景、机位和运动都为解释内容服务，不全程固定侧视，也不无目的绕圈。
- 每段设计完整的进入、预备、动作展开、变化、结果与接出，不是摆一个姿势。转场由对象和动作平滑接力，不能只切换画面，也不能靠推近静态物体冒充动画。
- 火柴人若被选用，头、躯干和四肢按线条/曲线绘制；可以由3D骨骼和IK/FK控制，但不变成圆柱、胶囊人或塑料玩偶。其他角色或无角色形式不强套这套外观。
- 用户选择2.5D时，通过物品厚度、空间位置、遮挡、视差、接触阴影和受控镜头建立层次，不只给2D图标加阴影。
- 按需使用Three.js、其他3D库或Blender，不限制为CSS/SVG平移，也不要求每片都安装某个库。先核实环境、授权与合成条件，工具不可用时说明情况，不悄悄降低效果。
- 主视觉文字按需跟随动作出现、停稳和退出，不固定每场标题；真实UI按所选形式加入，有角色才安排人物操作。
- 文案兼顾易懂与准确：解释必要术语、句子自然清楚，不写成论文摘要，也不靠口水话、网络梗、夸张承诺或鸡汤撑内容。
- [行为用例](evals/evals.json)覆盖前置询问、展现形式、声音方案、空间分镜、线条骨骼、UI素材和工具边界；保存用例不等于已经运行模型或渲染验证。
