# HyperFrames 动态视频提示词

把用户的主题整理成可直接制作的 HyperFrames 提示词，并单独交付旁白稿。用户本次要求优先，不复用其他视频的时长、数字、风格或路径。

## 1. 补齐必要输入

先从对话提取已有信息，只问会改变成片的缺项：

| 变量 | 处理方式 |
| --- | --- |
| 主题与核心结论 | 不明确时询问 |
| 视频时长 | 未提供时直接问“想做多少秒或多少分钟？” |
| 平台与画幅 | 能从平台推断就不问，否则按影响程度询问 |
| 视觉风格 | 沿用用户描述；确实无法决定时给简短选项 |
| 语言、旁白与字幕 | 优先从用户语言和上下文推断 |
| 数据、素材与保存目录 | 真实数据、指定素材或落盘需要时再问 |

一次最多问三个必要问题。如果只缺时长，就只问时长；用户说“你决定”时，选择合理值并简短说明假设后继续，不把确认过程变成长问卷。

## 2. 组织内容与音画分工

1. 先确定观众看完应记住的一句话，再按时长取舍内容。
2. 核实公式、数字和时效事实；演示假设和不确定性必须说清，不能包装成保证。
3. 画面负责关键数字、对象、变化和空间关系；旁白负责原因、推导、限制和行动建议。字幕可以复现旁白，但不能把旁白全文再次做成主视觉大字。
4. 先写旁白并校验自然朗读时长。让有效讲述覆盖大部分成片，只保留必要换气；过长时删减重复内容，不靠异常加速硬塞。
5. 再按旁白和视觉复杂度分配时间。时间轴从零连续覆盖总时长 `D`，最后一个时间点严格等于 `D`，无空档、无逐帧提示词。
6. 短视频减少支线和场景，长视频按章节推进；不把固定镜头数或示例节奏套到所有时长。
7. 参考具体作品时只提炼材质、镜头、节奏、色彩和信息密度，不复制可识别画面，也不冒充创作者。

## 3. 保持灵动，不做 PPT

按用户指定风格制作；没有要求时不强行套用 3D、实拍或某种模板。无论风格如何，都保持有意义的连续运动：

- 镜头或至少一个前、中、后景叙事层始终变化；文字稳定可读时，场景继续运动。
- 每段都有动作目标和视觉接力，转场优先用运动匹配、遮挡穿越、物体变形或空间衔接。
- 数字、图表和流程随叙事生长、流动或重组，不做“卡片淡入后静置”。
- 动效服务信息，不用抖字、无意义粒子、呼吸缩放或全画面弹跳冒充灵动。
- 根据总时长和语速决定视觉事件密度，不写死镜头数量或事件间隔。
- 使用 HyperFrames 支持的确定性、可 seek 主时间轴；循环、随机、相机与音画同步都应稳定复现。

平静、极简或商务风只降低运动幅度和密度，不产生意外冻结画面。

## 4. 交付两份 Markdown

### `[主题]-HyperFrames提示词.md`

给出一个可直接复制给 HyperFrames 的完整提示词，要求其直接创建并渲染成片，而不是只返回方案。按需要包含：

1. 主题、总时长、画幅、帧率、语言和交付格式。
2. 核心结论、数据口径、素材与必要免责声明。
3. 视觉系统、持续运动规则、转场和禁止项。
4. 连续时间轴：每段的起止时间、画面、镜头、屏幕文字、旁白和声音。
5. 渲染前验收：时长、静帧、字幕、数据、同步、溢出和音频。

### `[主题]-普通话旁白.md`

单独整理：

- 总时长、声音、语速和停顿要求。
- 带起止时间的分段旁白。
- 去掉时间码与制作说明的连续朗读稿，方便配音或 TTS。

两份文档中的旁白必须逐字一致，时间段连续覆盖总时长；这不代表旁白要复述画面。旁白文件不混入镜头、图表和转场指令。用户明确要求其他语言或无旁白时，以本次要求为准。

## 5. 保存与验收

用户指定目录时，以 UTF-8 保存两个文件；文件名使用本次主题并避开非法字符。写入前检查同名文件，不默认覆盖。用户要求落盘但没给目录时再问；没有落盘要求时，也把两份 Markdown 清楚分开。

交付前检查：

- 只使用本次变量，没有残留示例时长、数字、风格或路径。
- 时间轴连续且结束时间等于总时长。
- 旁白自然、信息充足、不过度抢读，没有无意义长空档，也不照读画面大字。
- 全片没有静态 PPT 段；动态持续但不影响阅读。
- 事实、公式、单位和两份文档中的旁白一致。
