# HyperFrames 动态视频提示词

把用户的主题整理成可直接交给 HyperFrames 的制作提示词。先问清变量，再安排内容；不沿用示例里的时长、金额、画幅或风格。

## 先确认变量

先从当前对话提取已有信息，只询问缺失且会明显改变结果的内容：

| 变量 | 处理方式 |
| --- | --- |
| 主题与核心结论 | 不明确时先问 |
| 视频时长 | 未提供时必须直接问“想做多少秒/分钟？” |
| 发布平台与画幅 | 会影响构图且无法推断时询问 |
| 视觉风格与动态程度 | 沿用用户描述；没有时给简短选项 |
| 语言、旁白与字幕 | 无法从上下文判断时询问 |
| 数据、素材与保存位置 | 需要真实数据、指定素材或落盘时再问 |

一次集中问完必要问题，不发长问卷。用户已给出的内容不要重复确认；用户说“你决定”时再按平台和主题选择合理值，并在结果前简短说明假设。

## 组织内容

1. 用一句话确定观众看完应记住什么，删除时长容纳不了的支线。
2. 核实公式、数字和时效事实；演示假设要写进画面或旁白，不能包装成保证。
3. 根据旁白与视觉复杂度分配时间，所有时间段连续覆盖用户给出的总时长 `D`，最后一个时间点严格等于 `D`。
4. 短视频减少场景而不是压缩大量文字；长视频按章节推进。只描述镜头、关键状态和时间轴，不逐帧写提示词。
5. 参考具体作品时提炼材质、镜头、节奏、色彩和信息密度，不复制可识别画面，也不冒充特定创作者。

## 动态设计

默认做成连续运动的 3D/动态图形视频，而不是幻灯片：

- 镜头或有意义的前、中、后景始终保持变化；重点文字稳定可读时，环境继续运动。
- 每个场景包含明确动作和视觉接力，转场优先使用穿越遮挡、物体变形、运动匹配或空间衔接。
- 图表在场景中生长、流动或重组，数字随旁白到达焦点；不把图表和说明堆成静态卡片。
- 动态服务叙事，不用抖字、无意义粒子和全画面弹跳假装灵动。
- 使用 HyperFrames 支持的确定性、可 seek 主时间轴；循环、随机、相机和音画同步都应能稳定复现。
- 根据成片节奏设置视觉事件频率，不把某个示例的秒数或镜头数量套到所有视频。

如果用户要求平静、极简或商务风，降低运动幅度和事件密度，但不要产生意外冻结画面。

## 生成两份 Markdown

默认交付两个独立文档。

### HyperFrames 主提示词

输出一个可直接复制的 `text` 代码块，按实际需求包含：

1. 输出规格：主题、总时长、画幅、帧率、语言和交付格式。
2. 视觉系统：原创风格、材质、色彩、字体、构图和可读性。
3. 动态约束：持续运动、转场方式、可 seek 时间轴与禁止项。
4. 完整时间轴：每段的起止时间、画面、镜头、文字和音效。
5. 逐段旁白：内容与时间轴一一对应，按自然语速校验能否说完。
6. 数据口径：公式、假设、来源边界和必要免责声明。
7. 验收项：总时长、静帧、字幕、数据、同步、溢出和最终渲染检查。

提示词要让 HyperFrames **直接创建并渲染成片**，不要只返回方案或代码片段。

### 普通话旁白轨道

另建一份 `[主题]-普通话旁白.md`，只包含：

- 标题、总时长和简短的声音要求。
- 带起止时间的分段旁白。
- 一份去掉时间码和制作说明的连续朗读稿，方便直接交给配音或 TTS。

旁白文字必须与主提示词完全一致，时间段连续覆盖总时长。不要把镜头、转场、图表等视觉指令混进旁白文件。用户明确要求其他语言或无旁白时，以本次要求为准。

## 保存与交付

用户指定目录时，以 UTF-8 分别保存主提示词和旁白轨道；写入前检查两个文件，不默认覆盖。用户要求落盘但没给位置时询问，不把桌面路径或具体主题文件名写死。没有落盘要求时，也要把两份 Markdown 清楚分开。

交付前检查：

- 使用的是本次输入变量，不残留旧示例的时长、数字或主题。
- 时间轴无空档，结尾时间与总时长一致。
- 独立旁白文件与主提示词逐字一致，并能在对应区间自然说完。
- 字幕不遮挡关键视觉。
- 全片没有无意的静态 PPT 段，动态也没有影响阅读。
- 事实、公式和单位一致；未验证内容明确标为假设。
